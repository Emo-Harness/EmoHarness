# EmoHarness Glossary

Terms are listed alphabetically. Each entry is the single agreed meaning inside this repository.

| Term | Meaning |
|---|---|
| **Audio clue (official)** | The `audio_clue/*_qwen2_audio_clues.json` files shipped with MME-Emotion. Generated by Qwen2-Audio and consumed by the official judge as ground-truth-side evidence. Never an input to the harness. |
| **Audio-model opinion** | The audio model's own coarse valence, arousal, and candidate emotion words, tagged as an opinion in the evidence record and treated as one voter, never as evidence. |
| **Builder gain** | Rec-S(L5) − Rec-S(L3): what the Builder added on top of the human scaffold with identical tools and inputs. The paper's central quantity. |
| **Builder** | The strong model (the teacher) that diagnoses Target failures and edits the harness. Currently GPT 5.6 Luna; an earlier run used Gemini 3.1 Pro. Never answers benchmark questions at inference time. |
| **Construction set (D_build)** | Examples the Builder may inspect, including labels, to discover failure patterns. Drawn from outside MME-Emotion (see ADR-0001). |
| **Content-addressed cache** | Store of every Target call keyed by model, decoding parameters, prompt text, and input hashes; guarantees identical inputs across methods and lets candidates reuse unchanged stages. |
| **CoT score (CoT-S)** | Official aggregate: `0.5 * Rec-S + 0.5 * Rea-S`. |
| **Evidence record** | The structured visual / audio / text evidence the harness assembles before asking the Target for a label. |
| **Evidence-gated labels** | Multi-label policy: a label is emitted only when at least one evidence item supports it and no cross-modal check contradicts it; at most three labels. |
| **External test set (D_ext-test)** | 300 external items evaluated once per frozen stage to measure validation overfitting; never used for selection. |
| **Format gain** | Rec-S(L2) − Rec-S(L1): the effect of the human cue checklist and the five-step output format in a single call. |
| **Gap Closed** | (Rec-S(L5) − Rec-S(L0)) / (Rec-S(L6) − Rec-S(L0)) on the paired subset; pre-registered tiers 0.25 and 0.5. |
| **Teacher Direct** | Upper-bound baseline (rung L6): the Builder model answers each benchmark item directly with the official prompt, frames plus audio text. |
| **Harness** | The versioned, executable bundle (prompts, configs, deterministic code, schemas) wrapped around the frozen Target. |
| **Held-out capability** | A task family whose data, labels, and name were never available during harness construction. Noise-ER, FG-ER, ML-ER, FG-SA, IR. |
| **Information firewall** | The tags, inspection rules, and tests in ADR-0012 that keep benchmark items, labels, and outputs away from every construction decision. |
| **Judge (official)** | GPT-4.1 step extractor followed by GPT-4o-2024-11-20 scorer with 10 frames at 1 fps, the official audio clue, and the gold label. |
| **Judge noise floor** | Rec-S and Rea-S differences between two passes of the official judge on the same 300 outputs; method differences below it are not interpreted. |
| **Label normalizer** | Local mapping of synonymous label strings (happy/happiness, angry/anger, sad/sadness, surprised/surprise, disgusted/disgust) used only for local scoring. |
| **Label set** | The closed candidate list inserted into the prompt for one item, together with the quantifier and noun the prompt carries. Owned by `data.label_set.LabelSet`: canonical lookup, answer parsing, cardinality, Recognition, precision/recall/F1. Varies per item inside ER-Wild and SA. |
| **Ladder** | The ordered methods L0–L6 where each rung adds one ingredient, so adjacent differences isolate modality, format, scaffold, and Builder effects. |
| **Leaderboard-comparable** | A score computed on all 6,500 items of a task family with the official prompt and official judge. |
| **Modality gain** | Rec-S(L1) − Rec-S(L0): the effect of appending audio-derived text to the official prompt. |
| **Output controller** | Deterministic, human-written code that turns the harness's internal result into the benchmark answer text. |
| **Pipeline calibration** | Optional check of our copy of the official pipeline against a published leaderboard number (Qwen2.5-VL-7B, 46.6 CoT); not part of the default plan since ADR-0015. |
| **Pre-registered subset** | 1,000 benchmark items, 125 per task, stratified by label with a fixed seed, whose id list is committed before any harness run. Used for every official-judge row that is not a full run. |
| **Pre-registration** | `docs/preregistration.md` at tag `prereg-v1`: hypotheses, metric, thresholds, hashes of the subset and manifests, frozen prompts and scaffold, analysis plan. |
| **Protocol gap** | Teacher Direct with native video minus Teacher Direct with the Target's frames-plus-text inputs; only measurable with a provider that accepts video (Gemini), not with the OpenAI teacher (ADR-0015). |
| **Proxy judge** | A cheaper stand-in for the official judge used only during construction. Must be calibrated against the official judge once. |
| **Qwen Direct** | Baseline: frozen Target, official prompt verbatim, native video input, one call. |
| **Reasoning score (Rea-S)** | Mean over non-final extracted steps of a 0/1 judge rating. A step is 0 only when it clearly contradicts visual or audio cues. Equals 0 when the response has a single step. |
| **Recognition score (Rec-S)** | Whether the final extracted step's emotion matches the gold label. For multi-label items, correctly predicted labels divided by gold label count. |
| **Regression set** | Construction-set items a previous harness version solved correctly. A candidate edit that breaks them is rejected. |
| **Scaffold gain** | Rec-S(L3) − Rec-S(L2): the effect of the structured multi-call pipeline over the best single call. |
| **Scoreboard** | The per-item scores of one row on one item set, from local predictions or official step scores, with one rule for macros and empty groups. Owned by `evaluation.scoreboard.Scoreboard`; the ladder, hypothesis tests, Builder gate, and calibration read scores only through it. |
| **Seen capability** | A task family whose *kind* of data was available during construction: ER-Lab, ER-Wild, SA. The MME-Emotion items themselves are still never seen. |
| **Stage 1 / 2 / 3** | Builder permission levels: Stage 1 human-written harness; Stage 2 Builder edits prompts and YAML; Stage 3 Builder also edits pure verification functions. Stage 2 output is the Prompt-Only baseline, Stage 3 is Full EmoHarness. |
| **Target** | The frozen small model whose answers are scored. Initially Qwen3-VL-8B. |
| **Validation set (D_val)** | External examples used only to select among candidate harness edits. Disjoint from D_build by source id and media hash. |
